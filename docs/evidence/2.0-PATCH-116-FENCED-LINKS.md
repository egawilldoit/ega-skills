## Defect

`brokenReferences()` in `packages/project/src/intake/quality.ts` applied
the Markdown-link regex over the complete file text, so links inside
fenced code examples were interpreted as real companion references.

Reproducer: `egawilldoit/skills`, skill `create-verification-workflow`,
file `references/feature-map-guide.md`. The links `./create-note.md` and
`./search.md` occur inside a fenced ```markdown example describing files
a consuming project would create; they are not references belonging to the
skill package. The validator incorrectly reported
`Q_BROKEN_COMPANION_REFERENCE` for both.

## Fix

`maskFencedCodeBlocks()` replaces fenced code blocks with spaces (newlines
preserved) before link matching: ``` and ~~~ fences, with or without an
info string; a backtick fence with a backtick in its info string is not a
fence; an unclosed or stray fence fails safe by shielding the rest of the
document. Real reference validation is unchanged: a genuine unresolved
Markdown link outside a fence still yields
`Q_BROKEN_COMPANION_REFERENCE`.
