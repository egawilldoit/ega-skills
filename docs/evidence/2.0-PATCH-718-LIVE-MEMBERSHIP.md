## Defect

`packages/mcp/src/hosted-runtime.ts` always built authorization from the
static `EGA_HOSTED_AUTHZ_JSON` / `EGA_HOSTED_AUTHZ_FILE` document
(`InMemoryControlPlane`, previously `:329-346`) and called
`controlPlane.authorize(hubId, subject, "read_hub")` (`:401`). The Supabase
resolver was wired only for `context_id` work (`:354-365`).

Consequence: with a live membership store configured, a DB-only revoke of
`workspace_memberships` did not deny unscoped hosted `search`. A subject whose
membership was revoked kept full unscoped search access with a token that was
still cryptographically valid.

## Scope

EGA-718 scope is limited to tracing UNSCOPED `search` authorization against
live membership and repairing any confirmed stale-authorization path. Not
included: new RBAC roles, auth UI rebuild, token-revocation UX, or any
cross-cutting permission redesign. Skill-scoped authorization, the deny sets,
and the static resource shape are deliberately unchanged.

## Fix

- `packages/mcp/src/hosted-supabase.ts`: the Supabase REST reader is factored
  into `createSupabaseRows`; new `createSupabaseMembershipAuthorizer` reads
  `workspace_memberships` (active row, workspace + subject scoped) on every
  call and delegates the decision to the existing `authorizeWorkspace`, so
  public reads, explicit private grants, and emergency denies keep their
  frozen semantics. Missing/duplicate/inactive/mismatched rows, unknown roles,
  and lookup errors all fail closed.
- `packages/mcp/src/hosted-runtime.ts`: when `EGA_HOSTED_SUPABASE_URL` and
  `EGA_HOSTED_SUPABASE_SECRET_KEY` are configured, unscoped reads
  (`skillId === undefined`, i.e. `search` and `resolve`) authorize through the
  live authorizer; everything else keeps the static control plane. No second
  control plane is introduced and the static document remains the source of
  the resource shape.
