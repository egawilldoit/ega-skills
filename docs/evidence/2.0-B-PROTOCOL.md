The modern revision (`2026-07-28`) is deliberately outside

  (`installModernOnlyHandlers`).
- `serveStdio` opens a connection in the modern era when the first request is
  a `server/discover` carrying a valid 2026-07-28 `_meta` envelope, and does
  the same install.

### Exact SDK client configuration used per era

`tests/mcp/helpers/sdk-era-client.mjs` builds an `EraClient extends
Protocol` on the installed SDK. SDK API used: `Protocol.connect/request/
notification/close`, `ProtocolOptions.supportedProtocolVersions`, the
documented `Client` seam `_outboundMetaEnvelope()`, and the protected
negotiated-version field the SDK's own negotiation sets (`Client.connect`
path; `setNegotiatedProtocolVersion` is not exported publicly, so the test
client assigns the same field after a successful required probe). The
transports are the only hand-written part (the SDK ships HTTP/stdio client
transports in `@modelcontextprotocol/client`, which is not a dependency here).

| Era | Client configuration | Handshake sent |
|---|---|---|
| legacy | `supportedProtocolVersions: ["2025-11-25"]` | `initialize {protocolVersion:"2025-11-25"}` then `notifications/initialized` |
| modern (no fallback) | `supportedProtocolVersions: ["2026-07-28"]` | one `server/discover` with `_meta` = `{protocolVersion:"2026-07-28", clientInfo, clientCapabilities}`; requires `supportedVersions` to contain `2026-07-28`; never calls `initialize` |
| auto (`versionNegotiation = auto` semantics) | `supportedProtocolVersions: ["2026-07-28"]` | probes modern first, pins modern when advertised; otherwise initializes legacy |

Observed negotiated versions: legacy `2025-11-25`; modern `2026-07-28`
(both HTTP and stdio). Modern HTTP requests additionally require the
standard headers `MCP-Protocol-Version`, `Mcp-Method`, and `Mcp-Name` for
`tools/call` (missing them is `-32020` from the SDK entry; observed while
probing, then implemented in the test transport).

## B12. Read-only runtime

`tests/mcp/runtime-read-only.test.mjs` hashes complete trees of the artifact
directory, a project directory with a valid `.egaskills.yaml` +
`.egaskills.lock`, and an unrelated source checkout; runs full legacy and
modern stdio sessions (all four tools plus refused file request); and hashes
again.

Result: artifact tree, project config/lock, and source tree are
byte-identical before/after; `registry.sqlite` mtime and size unchanged; no
`-wal`, `-shm`, or `-journal` files remain. A second test converts the
artifact registry to WAL, checkpoints it, rebinds the release package
digest, and repeats the sessions: the WAL-mode artifact also comes back
byte-identical with no sidecar files, exercising the documented read-only
open (`openReadOnlyRegistry`: read-write open, temp-schema FTS5 probe,
`query_only = ON`, clean close).

## Server fix

No server fix was required. B3/B6 modern discovery, `server/discover`
without `initialize`, per-result `_meta.serverInfo`, cacheable-result
`ttlMs`/`cacheScope`, and era gating all worked on the installed 2.0.0 SDK
with the existing `packages/mcp/src/server.ts` and the existing hosted
handler. All new tests were written against the real wire; none fall back
from modern to legacy, and none weaken or skip an existing assertion.

Observations recorded for follow-up (not fixed here, no correctness failure
for the acceptance tasks):

1. The hosted runtime maps tool-body `McpContextError` codes to
   `E_RUNTIME_UNAVAILABLE` (`packages/mcp/src/hosted.ts:177`), so a hosted
   `get_content` with `file_path: "hub-release.json"` returns
   `E_RUNTIME_UNAVAILABLE` rather than the frozen `E_CONTENT_FILE_UNKNOWN`.
   The artifact-only stdio runtime (the B9/B10 vehicle) produces the frozen
   code. Parity between eras holds either way; changing the hosted mapping
   is a product-behavior decision outside this branch's owned paths.
2. The intake publication E2E barrier waits 2 s for a spawned CLI to reach a
   test barrier (`EGA_TEST_RELEASE_PREVIEW_BARRIER`). Under contention on
   this 2-core host (load average ~5–7 from concurrent factory agents) the
   marker can arrive after 2 s; a debug copy with a 60 s wait passed. This is
   the existing timeout, not a product regression; no test was modified.
