# catalog-2026-09-24.1 — overlap analysis

Source-agent overlap analysis across the 48 active skills (exact duplicate bodies, similar descriptions, shared trigger vocabulary, near-identical intent).

## grilling / grill-me / grill-with-docs / wait-what
grilling is the primitive; grill-me and grill-with-docs are one-line wrappers delegating to it (grill-with-docs adds domain-modeling). grill-me and grill-with-docs have near-identical descriptions ('A relentless interview to sharpen a plan or design...') and near-identical bodies; ask-matt itself bakes in the rule 'if in a working directory use grill-with-docs, else grill-me'. Distinction rule: stateless interview vs stateful-with-docs; wait-what is distinct (backward-looking re-pitch of one message) but shares 'didn't land / plain English' vocabulary with grilling's shared-understanding goal. Recommended: collapse grill-me/grill-with-docs into one skill with a working-directory branch, keep wait-what separate.

## code-review / codebase-design / improve-codebase-architecture
All three share the deep-module vocabulary. code-review = diff-scoped review (Standards+Spec axes); codebase-design = interface-design vocabulary (reference, no process); improve-codebase-architecture = whole-repo survey producing an HTML report then a grilling loop. Overlapping trigger words: 'review', 'architecture', 'module', 'interface'. Negative cases cross-wire them (branch review vs repo survey vs single-module design).

## diagnosing-bugs / triage
Shared word 'bug'. diagnosing-bugs = a specific broken behaviour in code, feedback-loop-first; triage = the incoming issue queue on the tracker, bug or feature, no code diagnosis. triage even *verifies* claims by reproducing (step 3), which brushes against diagnosing-bugs' loop-building; the boundary is 'processing the queue' vs 'finding the root cause of one bug'.

## implement / prototype
Both produce code. implement = the real thing, from a spec/tickets, with TDD and code-review, committed to the branch; prototype = throwaway artifact answering one design question, committed to a throwaway branch at most. Shared trigger vocabulary: 'build', 'make', 'code it up'. Negative cases route quick demos to prototype and ticket-driven builds to implement.

## to-spec / to-tickets
Sequential pair on the same tracker. to-spec = conversation -> single published spec, explicitly no interview; to-tickets = spec/plan -> multiple tracer-bullet tickets with blocking edges. to-spec applies ready-for-agent to one spec; to-tickets applies it per ticket. Shared boilerplate (the prototype-snippet exception paragraph is duplicated nearly verbatim in both). Both gate on setup-matt-pocock-skills config.

## research / ask-matt
Both answer 'help me figure something out', but research investigates the world (primary sources, background agent, cited file) while ask-matt routes over the catalog (which skill/flow to run). Distinct; risk is only if ask-matt's vague description wins generic 'how do I do X' prompts.

## to-tickets / wayfinder
Both create tickets on the tracker. to-tickets: well-understood work, tracer-bullet vertical slices with blocking edges, agent-ready by construction. wayfinder: effort too big for one session, decision tickets (questions, not build slices), fog-of-war graduation, one ticket per session, hands off to to-spec at the end. ask-matt draws this line explicitly ('never a well-scoped feature').

## grilling / to-questionnaire
Both are question-centric. grilling interviews the user; to-questionnaire interviews the user only about the *send* and aims the questions at a third party. Shared words: 'questions', 'ask me/ask them'. Negative cross-cases included on both sides.

## handoff / to-spec
Both 'turn this conversation into a document'. handoff = lossy portable context file in OS temp dir for the next agent session; to-spec = authoritative spec published to the tracker with triage label. Shared trigger: 'turn this conversation into...'.

## setup-matt-pocock-skills (narrow-routing constraint)
Must NOT win generic setup/configuration tasks (ESLint, CI, venv, pre-commit). Its true trigger is configuring a repo for this skill suite specifically (tracker + triage labels + domain doc layout). All three negative cases target generic setup vocabulary ('set up', 'configure') that must route elsewhere.

## implement / tdd
implement drives tdd internally at pre-agreed seams; standalone tdd is for building a concrete behaviour test-first without a spec/ticket frame. Overlap is by design (composition), but routing should prefer tdd for bare test-first build requests and implement only when spec/tickets are in play.

## domain-modeling / codebase-design
Both are 'vocabulary layer' references that other skills call. domain-modeling = the *domain* language (CONTEXT.md, ADRs); codebase-design = the *architecture* language (deep modules, seams). ask-matt positions them as 'the words, not the process, are the problem'.
