## Defect

Skill-scoped hosted reads had no live-membership path at all. In
`packages/mcp/src/hosted-runtime.ts` the `authorize` wiring routed only
resource-level reads (`skillId === undefined`, i.e. `search`/`resolve`) through
the EGA-718 `createSupabaseMembershipAuthorizer`; every read with a `skillId`
fell through to `controlPlane.authorize(hubId, subject, "read_hub")`, i.e. the
static `EGA_HOSTED_AUTHZ_JSON` / `EGA_HOSTED_AUTHZ_FILE` document.

`packages/mcp/src/hosted.ts` gates `inspect` (register at `:355`, `requirePinned`
`:270`) and `get_content` (`:356`) only through `options.authorize`, so with a
live membership store configured a DB-only revoke of `workspace_memberships`
did not deny `inspect`/`get_content`. A subject whose membership was revoked
kept reading a known skill's content with a token that was still
cryptographically valid. Confirmed during independent verification of
EGA-718 / PR #153.

## Scope

EGA-755 scope is limited to routing skill-scoped authorization through the
existing live-membership authorizer and proving the revoke with the repo's
isolated PostgreSQL 16 RLS harness. Not included: RBAC redesign, auth UI,
token-revocation UX, cross-cutting permission changes, or a second control
plane.

## Fix

- `packages/mcp/src/hosted-runtime.ts`: the single `authorize` callback now
  consults the same live authorizer for both resource-level reads and
  skill-scoped reads (`inspect`, `get_content`, via `SKILL_SCOPED_READ_TOOLS`).
  The static document still owns the resource shape (workspace, visibility,
  owner, explicit private grants) and the emergency deny for the resource id
  (`denied: policy.denies.includes(hubId)`); the live authorizer only decides
  who currently belongs. Lookup failure, malformed/duplicate/inactive rows, and
  unknown roles fail closed.
- The per-skill projection inside an unscoped search/resolve keeps the static
  control-plane decision: the resource-level check for that request already ran
  against the live store, and this avoids an N+1 live fan-out (one read per
  skill) on every search.
- Personal / no-live-store mode is unchanged: with no Supabase store
  configured, `controlPlane.authorize` remains authoritative and zero live
  reads occur.
- `packages/mcp/src/hosted-supabase.ts`: doc comment updated (the authorizer is
  no longer "unscoped only"). No behavior change.

No RBAC redesign, no auth UI. Deny sets, public visibility, explicit grants,
fail-closed behavior, and immutable release/blob/version identity are
preserved.
