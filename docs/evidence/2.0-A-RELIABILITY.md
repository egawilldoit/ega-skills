## Root cause

Two independent defects in the same test file, both able to hang `node --test`
forever:

1. **Late exit listener (release-blocking hang).**
   `tests/mcp/retained-serving.test.mjs` waited for a child process exit with
   `new Promise((resolve) => child.once("exit", ...))` attached *after* awaited
   file polling (`await waitForFile(resultB)`). `ChildProcess` replays no `exit`
   event, so when the child had already exited before the listener attached, the
   promise never settled and the test file never completed. `node --test` has no
   default test timeout, and Node 24 does not force test-file processes to exit,
   so the runner waits forever (`--test-timeout` cancels the test but the file
   process stays alive; measured below).

2. **Partial read of the child result file (fast flake).**
   The child wrote its result with `writeFileSync`, and the parent polled only
   for existence before `JSON.parse`. A poll landing between create/truncate and
   write produced `SyntaxError: Unexpected end of JSON input` (observed once in
   `/tmp/opencode/release-a/probe/force-naive.out`, an unmodified copy of the
   working tree at that time).

### Evidence 1 - CI attribution to the file

- The runner reports a file's test results only once that file completes; with a
  hung file, later files' results are buffered and never printed. Proven with a
  controlled pair of files (`/tmp/opencode/release-a/probe/ordering.out`):
  with `a-hang.test.mjs` pending and `b-ok.test.mjs` passing,
  `node --test --test-concurrency=2` exited 124 and never printed
  `✔ b-ok: completes` until interruption.
- Therefore the last CI line (`resolve (wire): task resolution over stdio`,
  `tests/mcp/resolve.test.mjs`) is the last *completed file* before the hang.
- Discovery order in this repo places `tests/mcp/retained-serving.test.mjs`
  immediately after `tests/mcp/resolve.test.mjs`. The four last files printed in
  CI (`inspect`, `multi-user-http-smoke`, `project-boundary`, `resolve`) are
  exactly discovery indices 35-38 (`/tmp/opencode/release-a/order.json`), so the
  hung file is index 39: `tests/mcp/retained-serving.test.mjs`.
- Test-step accounting: 315 top-level tests completed with a summed duration of
  93.3 s inside a 35.3 s window, consistent with the runner's 3 concurrent file
  slots; only one test-file child was still alive at cancellation
  (`Terminate orphan process: pid (4546) (MainThread)`), exactly as expected when
  one file hangs and its siblings finish.
- The file is new in the PR that introduced the hang (added by merge `22593646`,
  360 lines).
- The hang does not reproduce locally: the latency between "result file
  observed" and "child exit event" is much larger under this VM's CPU pressure,
  so the listener usually attaches first. In a 12-run instrumented loop
  (`/tmp/opencode/release-a/probe/race/observations.log`) the child was always
  still running at attach time on this box - the race is latent locally and
  fatal on a fast 4-vCPU runner.

### Evidence 2 - deterministic reproduction of the hang and the fix (A/B)

Real test body copies (`/tmp/opencode/release-a/probe/race-*.test.mjs`) with a
forced 750 ms gap between the second child's result file and the exit-listener
attach:

| Variant | Helper | Result |
| --- | --- | --- |
| `race-naive` (HEAD helper) | `child.once("exit", ...)` only | exit **124**, 1 test cancelled, no output for later tests after 90 s bound |
| `race-fixed` (working tree) | exits state checked first | exit **0**, 8/8 pass in 7 s |

### Evidence 3 - Node 24 runner semantics (why the hang is unbounded)

Probes in `/tmp/opencode/release-a/probe/`:

- `leak-server`, `leak-timeout`, `leak-interval`, `leak-child`: each left one
  open handle after all tests passed; `node --test` never exited (exit 124 at
  the 20 s bound).
- `node --test --test-timeout=3000 leak-server.test.mjs`: still exit 124; the
  test is cancelled (`ℹ cancelled 1`) but the file process stays alive. A
  per-test timeout alone cannot bound the suite.
- `node --test --test-force-exit leak-server.test.mjs`: exit 0 and the leak is
  invisible - force-exit is masking and is deliberately not used by the release
  gate.
- `late-listener.test.mjs`: naive helper exit 124; exit-state-aware helper exit
  0.

## Fix

`tests/mcp/retained-serving.test.mjs`:

- `waitForChild` now returns the already-recorded `exitCode`/`signalCode`
  immediately when the child has already exited, and otherwise attaches the
  `exit` listener.
- Child results are published atomically (`writeFileSync` to a temp path +
  `renameSync`), so a poll can never observe a partial result document.

Defensive lifecycle hardening in the same failure class (no product behavior
change, no test disabled):

- `tests/project/hub-adoption.test.mjs`: the child-side lock-contender barrier
  loop is now bounded at 120 s and reports `E_TEST_BARRIER_TIMEOUT` instead of
  spinning forever when a parent assertion fails before writing the release file.
- `tests/cli/intake-publication-e2e.test.mjs` and
  `tests/project/intake-adoption-apply.test.mjs`: the barrier child is killed in
  `t.after` when the test exits without consuming it, so a failed bounded wait
  can no longer leave a survivor holding the file open.

## Bounded CI test step (A7)

`package.json`:

- `test` stays `node --test` for local use (documented difference: no bound).
- `test:ci` is `node scripts/release/run-tests-bounded.mjs`, which runs
  `node --test --test-timeout=<per-test>` in a new process group and enforces an
  overall wall-clock bound (default 25 min; `EGA_TEST_PER_TEST_TIMEOUT_MS` /
  `EGA_TEST_OVERALL_TIMEOUT_MS` override). On expiry it prints the surviving
  descendant process list (naming the stuck `.test.mjs`), kills the tree
  (SIGTERM then SIGKILL), and exits 124.
- Rationale recorded in Evidence 3: `--test-timeout` alone leaves the file
  process alive, so the overall bound is required to convert a leak into a
  bounded, evidenced failure.
- Bound justification: the longest single test observed locally is
  `x10 determinism: 41 ROUTER scenarios...` at 296.8 s on a contended 2-core VM
  (pre-fix full run: 218.0 s), and the whole Linux CI suite is ~2.2 min. A
  10-minute per-test and 25-minute overall bound therefore leaves a wide margin
  for a slow runner while still failing within one job window instead of one
  workday. Both bounds are environment-overridable for diagnosis.
- Both workflow `Test`/`Full test suite` steps now run `pnpm test:ci`.

## Residual risks and cross-agent notes

- Product-source test-only barriers remain unbounded and can turn a failed
  bounded wait into a hang if a test abandons a barrier child:
  `packages/cli/src/commands.ts` `releasePreviewBarrier` (unbounded
  `Atomics.wait` loop) and `packages/project/src/intake/adopt.ts`
  `adoptionCrashBarrier` (unbounded). `packages/mcp/src/retained.ts`
  `retainedBarrier` is already bounded at 30 s. Recommended follow-up (product
  owner): add the same deadline. Not changed here because it is product source
  outside this workstream's ownership rule.
- Locally observed flake in `tests/cli/intake-publication-e2e.test.mjs`: during
  the A1 run the parent's bounded poll for the preview barrier marker expired at
  ~29 s while the CLI child had not yet published the marker. The file and the
  suite still terminated (the child was not left spinning), so this is a
  bounded failure, not a hang. The same test passed in isolation (1/1, 14.2 s)
  immediately afterwards, and CI executed it in 7.7 s. The new `t.after` kill
  guarantees a failed wait cannot leave a survivor. Root-cause hardening of the
  unbounded preview barrier itself belongs to the product owner (see above).
- Scope exception: the root cause lives in `tests/mcp/**`, which this
  workstream was asked not to modify. The fix is the minimal lifecycle change in
  that file plus the regression/hardening tests; the main agent should route the
  change through the MCP test owner for awareness.
- Cross-agent assumption: `pnpm build` output is current before tests run; the
  release gates and CI both run `build` before any test stage.
